# IA 推导与页面规格

## 一、推导链（顺序不能跳）

```
实体 → 角色 → 任务链 → 页面 → 区域 → 组件
```

### 1. 实体

从 brief 里抠名词。每个实体写出**生命周期**，生命周期决定状态，状态决定页面。

例：订单 → 待确认 / 运输中 / 使用中 / 归还中 / 已完成 / 已取消
例：设备 → 在库 / 已锁定 / 在途 / 使用中 / 待入库 / 检测中 / 维修中 / 已报废

### 2. 角色

不同角色看同一实体，页面不同。别只写「管理员 / 普通用户」，要写**这个人此刻在完成什么**：

| 差 | 好 |
|---|---|
| 运维人员 | 仓库值班：今天要把退回的设备入库检测并重新上架 |
| 客户 | 项目负责人：要确认设备到货并安排夜间迁移窗口 |

### 3. 任务链

每个角色写出主干任务，用动词短语，三步以内：

```
下单 → 收货 → 迁移 → 归还
受理 → 发货 → 入库 → 上架
```

任务链上的每个节点对应一个页面或一个弹窗。**链外的东西一律不进 v1。**

### 4. 页面三问（防凑页数）

| 问 | 答不上来说明 |
|---|---|
| 承接哪个上游动作？ | 入口不明，用户到不了 |
| 把用户送去哪？ | 死胡同 |
| 没有它哪个任务会断？ | 可有可无，删 |

### 5. 页面清单表

```markdown
| 编号 | 页面 | 角色 | 承接 | 去向 | 核心内容 |
|---|---|---|---|---|---|
| 01 | 订单列表 | 客户 | 侧栏/概览 | 详情 / 新建 | 状态筛选 + 表格 |
```

编号用来命名 Figma 画板（`01 客户 · 订单列表`），也用来对 HTML 的路由 key。

## 二、页面规格模板

每页一份，放在 `spec/{page-id}.md`。

```markdown
# 02 订单列表（客户）

## 布局
- 页头：标题 + 副文案 + 主操作（创建订单，每屏唯一 primary）
- 筛选条：状态 chips + 搜索框
- 表格：订单号 / 设备数量 / 状态 / 创建时间 / 确认时间 / 操作
- 页脚：总数 + 分页

## 数据
读 Order：id, qty, status, createdAt, confirmedAt, project

## 状态
| 状态 | 条件 | 显示 |
|---|---|---|
| 正常 | 有数据 | 表格 |
| 空 | 筛选无结果 | 「没有符合条件的订单」+ 清空筛选 |
| 加载 | 首次进入 | 3 行骨架屏 |

## 跳转
| 触发 | 条件 | 目标 | 参数 |
|---|---|---|---|
| 行点击 | 任意状态 | 04 订单详情 | orderId |
| 创建订单 | — | 03 创建订单 | — |
| chips | — | 本页 | status filter |
```

### 为什么必须有「状态」和「跳转」

只写布局和组件的规格，结果是：HTML 出来点不动，Figma 出来没有连线。
**状态决定 HTML 的分支，跳转决定两端的连线。** 这两块缺了，后面两条出口都只剩截图。

## 三、跨页状态机（多页联动项目必写）

一端操作改另一端数据时，先画状态机再写页面：

```markdown
| 当前状态 | 触发方 | 动作 | 下一状态 | 副作用 |
|---|---|---|---|---|
| 待确认 | 客户 | 取消 | 已取消 | 释放锁定库存 |
| 待确认 | 运维 | 受理发货 | 运输中 | 设备转「在途」 |
| 运输中 | 客户 | 确认收货 | 使用中 | 开始计时 |
| 使用中 | 客户 | 申请归还 | 归还中 | 生成寄回单 |
| 归还中 | 运维 | 入库检测 | 检测中 | 设备转「检测中」 |
| 检测中 | 运维 | 上架 | 已完成 | 设备回「在库」，订单闭环 |
```

写完后核对：**每个状态是否都有出口？** 没有出口的状态 = 用户卡死。

---

## 四、双端项目的划分

同一产品有客户侧和管理侧时：

- 共用一套实体与状态机
- 各自有独立导航与首页（不要用同一套侧栏换菜单）
- 顶栏放视角切换（原型里必须可点，这是演示时最常被点的东西）
- 一端的动作要在另一端的待办里看得见 —— 否则联动是假的
