# 视觉双轨与反模板评审

## 一、定轨

```yaml
b_end: 后台 / 管理端 / 运营 / 客服 / 审核 / 配置 / 报表 / 权限
       使用者为内部员工；高密度表格；批量操作
c_end: App / 小程序 / H5 / 用户端 / 消费者端
       浏览 / 下单 / 个人中心 / 支付 / 转化；单屏主任务
```

规则：
- 每页必须标 `surface`，混合产品按页标，不按项目标
- 禁止拿 B 端 token 画 C 端页，反之亦然
- brief 模糊就问一次「内部用还是用户用」

## 二、B 端 token（utilitarian-enterprise）

| 项 | 值 |
|---|---|
| 画布 | 1440×900 |
| 侧栏 | 208px，`#001529`，菜单项高 40，选中态 `#002140` + 左侧 2px 橙条 |
| 页背景 | `#F0F2F5` |
| 卡片 | `#FFFFFF`，圆角 8，**无阴影**，`#E8E8E8` 描边分区 |
| 主色 | `#1677FF`；主色浅底 `#E6F4FF`；主色描边 `#91CAFF` |
| 辅助色 | 橙 `#FA8C16`（进度/提醒）、绿 `#52C41A`、红 `#FF4D4F` |
| 文字 | `#141414` / `#595959` / `#8C8C8C` |
| 字号 | 页标题 20/28 semibold；卡片标题 14/22 medium；正文 13/20；辅助 12/20 |
| 数据 | SF Mono 12（订单号、SN、时间） |
| 圆角 | 按钮 6 / 卡片 8 / 标签 4 / **最大 8** |

密度规则（B 端最重要的三条）：
1. 列表用 **flat table**，禁止 card 套 table
2. Dashboard KPI **≤ 3**，超了说明没想清主指标
3. 每屏 primary 按钮 **≤ 1**

3. 单屏一个标题层级，不要 18 和 20 混着用

## 四、通用禁令

| 类别 | 禁止 |
|---|---|
| 字体 | `Inter` / `Roboto` / `Arial` 作中文正文（Figma 里用 PingFang SC / 思源黑体） |
| 颜色 | `#6366F1`、紫蓝渐变、霓虹深色侧栏 |
| 布局 | card-in-card 超过 1 层；非 dashboard 用 4 等宽 KPI |
| 装饰 | 与信息无关的渐变、光斑、几何装饰 |
| 间距 | 非 4 的倍数（允许 4/8/12/16/24/32/48） |

## 五、反模板评审清单（逐条打勾，任一 FAIL 回改 design-plan）

**AI 默认三套皮** —— 除非 brief 明确要求，命中即 FAIL：

1. 奶油纸 `#F4F1EA` + 高对比衬线标题 + 陶土色 accent
2. 近黑底 + 单一酸绿/朱红 accent
3. 报纸风密排 + 零圆角 + 发丝线装饰

**换皮测试（最关键的一条）**：把 design-plan 里的产品名换成一个不相关的产品，如果整段描述仍然成立，说明这是模板，不是为这个 brief 做的 —— 改写。

**结构检查**

- [ ] 每页能说出「这一屏唯一的任务是什么」
- [ ] 表格列都能对应到实体字段，没有装饰列
- [ ] 主操作按钮在视觉上唯一（同屏没有两个同权重的强调）
- [ ] 空态、加载态都设计了
- [ ] 没有为了填满而存在的区块

**视觉检查**

- [ ] 色值全部来自 token 表，无随手 hex
- [ ] 字号层级 ≤ 4 级
- [ ] B 端无阴影墙；C 端阴影只有一层
- [ ] 中文正文不是 Inter

**结论写法**

```markdown
## 反模板评审结论
- surface: b_end
- 命中项: KPI 原本 4 个；卡片用了阴影
- 修订: 合并为 3 个 KPI；阴影改描边
- 结论: PASS
```

## 六、记忆点（每项目 1 个）

记忆点必须**承载信息**，不能是纯装饰：

| 好 | 差 |
|---|---|
| 订单生命周期轨道，当前节点脉冲 | 顶部一条渐变色带 |
| 设备容量进度环，颜色随水位变化 | 背景几何光斑 |
| 双端切换时侧栏色温变化（明示当前身份） | 卡片悬浮动效 |

定完写进 `design-plan.md` 的 记忆点 节，并在两个出口都实现它。
