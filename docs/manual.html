00它给你什么

先搞清楚交付物长什么样，再决定怎么装。

你给它一段需求描述，它给你三样东西：

① 交互原型（HTML）

单个 .html 文件，双击就能在浏览器打开。页面之间能跳，按钮能点，状态会变，弹窗会弹。可以直接丢到群里给老板和开发看。

② Figma 插件

一个文件夹，导入 Figma 桌面端跑一次，11 个画板连同 Auto Layout 和点击连线一起长出来，之后在 Figma 里正常编辑。

③ 设计规格文档

需求简报、信息架构、视觉定轨、逐页规格（含状态与跳转）。这是给开发看的东西——接口要什么字段、状态怎么流转、点击去哪，都写在里面。

和传统做法比，省在哪

做法你拿到什么代价
直接画高保真稿静态图，点不动改一版重画一遍
写页面代码再截图只有外观，逻辑靠嘴讲开发照着猜状态
导 .fig 交付做不到——私有二进制格式，没有对外写入接口—
这套方法可点的原型 + 可编辑的 Figma 图层 + 规格文档先花 2 分钟把需求说清楚

01五种安装方式

按你的情况挑一种。不用全做，做完一种就能用。

方式适合谁生效范围能不能一键更新
A · 让 AI 帮你装不想碰命令行你的所有项目能
B · 自己敲一行命令会开终端你的所有项目能
C · 装进项目里团队共用同一套只有这个项目能
D · 下载 ZIP公司网络挡了 git你选的位置要重下
E · 不装，临时用只想先看看效果当次对话不支持

装到哪？这个工具只认两个目录：用户级 ~/.workbuddy/skills/（所有项目都能用），项目级 <你的项目>/.workbuddy/skills/（只有这个项目能用）。放错地方它是发现不了的。

方式 A · 让 AI 帮你装 推荐

不用记命令。打开对话，把下面这句话复制过去：

帮我把 https://github.com/JS-Carrot/product_skills 这个仓库装成我的用户级 skill，目录名用 product-prototype-generator

它会自动完成克隆、改名、校验。装完你会看到 ~/.workbuddy/skills/product-prototype-generator/ 这个目录，里面有 SKILL.md、references/、templates/、scripts/、examples/。

方式 B · 自己敲一行命令

打开「终端」，粘贴执行：

# 用户级安装：一次装好，所有项目可用
git clone git@github.com:JS-Carrot/product_skills.git ~/.workbuddy/skills/product-prototype-generator

如果提示 Permission denied (publickey)，说明这台机器还没配 GitHub 的 SSH 密钥。两个办法：换成 HTTPS 地址 https://github.com/JS-Carrot/product_skills.git，或者让 AI 帮你配密钥。

方式 C · 装进项目里，团队共用

想让整个团队拉下项目就自带这套能力，装到项目目录，并把它提交进仓库：

# 在项目根目录执行
mkdir -p .workbuddy/skills
git clone git@github.com:JS-Carrot/product_skills.git .workbuddy/skills/product-prototype-generator

# 别加进 .gitignore，要提交，队友拉下来才有
git add .workbuddy/skills/product-prototype-generator
git commit -m "chore: 引入产品原型生成器"

注意：项目级安装会把这 300KB 源码一起提交进你们的业务仓库。如果团队介意，改用方式 A 或 B，各自装在自己的机器上。

方式 D · 下载 ZIP（没有 git 也能装）

  1. 打开仓库页面

    浏览器进 github.com/JS-Carrot/product_skills。

  2. 下载压缩包

    点右上角绿色的 Code 按钮 → Download ZIP。

  3. 解压并改名

    解压得到 product_skills-main 文件夹，必须改名为 product-prototype-generator。名字错了会失效。

  4. 放到指定目录

    把整个文件夹拖进 ~/.workbuddy/skills/。Mac 上在 Finder 按 ⌘⇧G，输入 ~/.workbuddy/skills 直达。

方式 E · 不装，临时试一次

只想先看看它出的东西合不合口味，可以完全不安装：

  1. 打开 SKILL.md 原文

    仓库首页点开 SKILL.md，点右上角 Raw，全选复制。

  2. 贴给 AI，加一句话

    粘贴后补一句：「按上面这份流程帮我做原型，产出可点击的 HTML」。

这样能用上它的方法论，但用不了配套的模板和校验脚本（templates/figma-kit.js、scripts/test-html.js），Figma 出口基本做不出来，产出也没人帮你验证。确认好用之后，还是回到方式 A 或 B。

装完自检：30 秒确认成功

新建一个对话，只说三个字：

画个原型
装对了 它会先反问你：产品是什么、谁用、单屏主任务、关键实体——四个问题，缺哪个问哪个。这说明技能被正确加载了。
没装对 它直接开始编一个页面，或者反问你「你想做什么产品呀」这种开放式问题。说明技能没被识别，检查目录名和位置。

以后怎么更新

仓库有更新时，进安装目录拉一次就行：

cd ~/.workbuddy/skills/product-prototype-generator
git pull

ZIP 方式装的没法这么更新，得重新下载覆盖。

02怎么写需求

这一节决定产出质量。需求说清楚，返工少一半。

它只认四件事。你把这四件说全，它就能开工；说漏了，它会先问你——不会硬猜。

要素要回答什么为什么重要
产品是什么一句话说清决定它的行业语境和用词
谁用内部员工，还是普通消费者这一句决定整套视觉走向：后台走紧凑高效，前台走大留白大按钮
单屏主任务用户进来最想完成的那件事决定首屏放什么，防止什么都想放
关键实体订单、设备、会员、工单……页面是由实体生命周期推出来的，不是拍脑袋列的

可以直接抄的模板

【产品】一句话说明是什么。
【谁用】内部运维人员 / 普通消费者（二选一，或说明哪几页给谁用）。
【单屏主任务】用户进来最想完成的那件事，一句话。
【关键实体】订单、设备、供应商……（列出 2-4 个）。
【核心流程】从开始到结束经过哪几步，比如：下单 → 审核 → 发货 → 使用 → 归还。
【必须有的页面】如果有硬性要求就列出来，没有就写「你按流程推」。
【交付】要可点击的 HTML + Figma 插件 + 规格文档。

好坏对照

✕ 这样问，产出会很空 「帮我做一个设备管理系统的原型，要好看一点，功能全面一些。」

没有说谁用、没有主任务、没有实体。它只能给你一个「什么都有、什么都用不上」的通用后台。

✓ 这样问，能直接出东西 「给客户做一个车载数据迁移的下单系统。客户是外部企业的运维负责人，进来主要看自己订的设备和订单进度。核心实体是订单和设备。流程是：下单选设备数量 → 等待确认 → 运输中 → 使用中 → 归还 → 检测完成。另外要一套运维后台，管设备出入库和订单受理。」

四要素齐全，还给了状态链。这种需求能一次出到 11 个页面。

一个省事的技巧：手上有 PRD、需求文档、竞品截图，直接把文件丢给它，再说一句「按这份文档做原型」。它读文档比听你口述准。

03怎么开口

三种说法都能触发，不用背咒语。

说法例子适用
自然描述「帮我画个 XX 系统的原型，要能点」日常，最省事
带触发词「出个交互原型」「做个 Figma 稿」「画后台页面」「出个 App 页面」想确保它一定被调用
直接点名「用 product-prototype-generator 做」装了多个技能，怕打架

它认得的触发词

画原型 · 出个能点的原型 · 交互原型 · Figma 稿 · 后台页面 · App 页面 · 小程序原型

反过来，这些说法它不会接：「画个图」「做个设计」「帮我美化一下」——太泛，可能触发别的能力。想画原型就把「原型」两个字说出来。

04它怎么干活

九个阶段，三个必须停下来的卡点。知道流程，你就知道该在什么时候说话。

三个你该出声的时刻

① 它问你四个问题的时候

别嫌烦，这是它在收口。这时候补充一句「哪几页是给内部人用的」，能省掉后面整轮返工。

② 它给出页面清单、还没开始画的时候

这是最后一个低成本改结构的节点。页面少了现在说，比画完再说便宜十倍。如果你觉得它多列了一个用不上的页面，直接说删——它有条规则叫「三问答不上就删页」，你可以拿这条要求它。

③ 它说「验证全绿」的时候

意味着它真的点过每个按钮、扫过宽度溢出。这时候产物才可信。

为什么它有时候会「顶」你？它有几条硬规则：没说清需求不推导架构、视觉评审不过不出图、页面规格缺状态和跳转就不进生成、验证没过不算交付。这些不是摆架子，是为了避免你拿到一个点不动的漂亮壳子。

05产物怎么用

两个出口，两种用法。都不需要装任何软件。

出口 1 · 交互 HTML

  1. 双击打开

    找到 index.html，双击。默认浏览器打开，不需要联网，不需要起服务。

  2. 点着走一遍主流程

    侧栏切页面，表格行点进详情，按钮触发状态变化——弹窗、Toast、空态都会有反馈。

  3. 发出去

    就一个文件，微信、飞书、邮件附件都能直接发。收到的人双击就能看，不用装任何东西。

演示技巧：投屏时用浏览器的「全屏」（⌃⌘F），再按 ⌘+ 放大到 125%，会议室后排才看得清。

出口 2 · Figma 插件

这个稍微特殊：它不是一张图，而是一个能在 Figma 里跑的小程序，跑一次就把画板画出来。

  1. 前提：必须用 Figma 桌面端

    网页版装不了本地插件。没装的话去 figma.com/downloads 下客户端，登录同一个账号。

  2. 新建一个空文件

    打开桌面端，新建 Design file。建议新建，别在正式稿里跑。

  3. 打开插件导入菜单

    顶部菜单 Plugins → Development → Import plugin from manifest…

  4. 选 manifest.json

    在文件选择框里找到项目下的 figma-plugin/manifest.json，选中打开。注意选的是 manifest.json，不是 code.js。

  5. 运行

    菜单 Plugins → Development → 找到 产品原型生成器，点击运行。几秒钟后画板出现。

如果你用的是 Figma 免费版（Starter）：可能会弹「The Starter plan only comes with 3 pages」。这是因为免费版最多 3 个页面，插件想新建第 4 个。插件已经内置了降级处理——它会改用当前页面承载，照常出图，不用管这个提示。

跑完你会看到

  • 每页一个画板，1440 宽，图层是原生的 Frame / Text / Shape，能直接改
  • 自动布局已配好，改文案不会把排版撑坏
  • 点击连线已连好，切到 Prototype 面板按播放键就能点着跳

它做不到什么（说在前面）

  • 不会生成 .fig 文件——那是 Figma 的私有二进制格式，没有对外写入接口，任何人都做不到
  • 不产出组件——出的是 Frame 层，要做组件库得自己再封装一遍
  • Figma 里不会「演」逻辑——点击只能跳转，状态变化要在 HTML 版里看

出口 3 · 规格文档

给开发的那一份。打开顺序就是信息从粗到细的顺序：

文件里面是什么谁看
brief.md产品定位、用户、主任务、关键实体所有人，先看这个
ia-draft.md页面清单 + 每页承接什么动作、送去哪产品 / 设计评审
design-plan.md视觉走向、色值字号、记忆点设计 / 前端
spec/*.md逐页：布局、数据、状态、跳转开发，写代码就看这个

06怎么改需求

改需求有正确姿势。说错一句话，它会把整个原型重画一遍。

✕ 不要说 「整体再改改，感觉不太对。」

它只能整页重做，上一版你满意的细节全丢，而且每次重做结果都不一样。

✓ 要说 「订单详情页的设备列表，把状态列挪到数量前面，其他不动。」

只动一处，其余原样保留。改十次也不会把整体改乱。

三种改动，说法不同

改什么怎么说它会做什么
改结构
加页、删页、改流程		「加一个设备保养记录页，从设备详情进去」改规格 → 两个出口同步加
改视觉
颜色、间距、字号		「主色换成深蓝，卡片圆角从 8 改成 12」改 token → 两个出口同步换
改文案
措辞、标签		「把所有『确认订单』改成『提交订单』」只改文字，不动结构

一条经验：一次只说一处改动，改完看一眼再提下一个。比起一口气提十条，这样返工率低得多——因为你能立刻发现哪条理解偏了。

07常见问题

装和用的时候最容易卡住的八个点。

Q1 说了「画原型」，它没反应／还是自己乱编

先确认装没装对：目录必须是 ~/.workbuddy/skills/product-prototype-generator/，里面直接有 SKILL.md（不是套一层 product_skills-main/SKILL.md）。再不行就点名调用：「用 product-prototype-generator 这个技能做」。

Q2 装完当前对话没生效

技能是新开对话时加载的。装完关掉当前窗口，重开一个再说。

Q3 HTML 打开是白屏，或者点了没反应

大概率是用文本编辑器在预览。要用浏览器打开——右键文件 → 打开方式 → Chrome / Safari。还不行就在对话里说「HTML 打开是白屏」，让它跑一遍验证脚本查原因。

Q4 Figma 里找不到 Import plugin from manifest

两个原因：一是你在用网页版，必须换桌面端；二是菜单路径找错了，正确路径是 Plugins → Development → 最下面那一项。

Q5 运行插件报「Starter plan only comes with 3 pages」

免费版 Figma 最多 3 个页面。插件已内置降级：会自动改用当前页面承载，照常出图。看到这个提示不用管，等几秒画板就出来了。

Q6 觉得产出太「模板」，跟别人家撞脸

把这句话丢给它：「跑一遍反模板评审，把设计说明里的产品名换成别的产品，看那段描述还成不成立。」它会自己找出模板化的部分重做。你也可以直接说「这个页面太像通用后台了，给我一个只属于这个业务的细节」。

Q7 能直接给我一个 .fig 文件吗

不能。.fig 是 Figma 的私有二进制格式，官方没有开放写入接口，任何工具都生成不了。这个技能给的是「在 Figma 里跑一下就把画板长出来」的插件，效果上等价，但路径不同。有人跟你说能直接生成 .fig，那是在忽悠。

Q8 生成的时候要联网吗？数据会不会外泄

画原型这一步是模型在生成内容，跟你平时对话一样。但生成出来的产物本身完全离线：HTML 单文件零外链，不请求任何外部资源，断网也能打开；Figma 插件声明了不允许任何网络访问。公司内网环境可以直接用。

团队里怎么推广

最省事的做法：把仓库地址发到群里，让每个人用方式 A 自己装一次，一句话搞定，互不干扰。如果希望全组产出风格统一，就走方式 C 装进项目仓库，这样大家用的永远是同一版。
